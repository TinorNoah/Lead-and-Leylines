# Installed catalog maintenance

How the browsable mod list stays in sync with the pack. Agent skills (`add-mod`, `publish-release`) are short checklists; this file is the policy.

## Who updates what

| File | Who edits it | When |
|---|---|---|
| [`catalog.toml`](catalog.toml) | Human or agent, **by hand** | Every add, remove, or regroup of a packwiz entry under `pack/mods/`, `pack/resourcepacks/`, `pack/tacz/`, or `pack/pointblank/` |
| [`catalog.json`](catalog.json) and `docs/installed/*.md` | **Never by hand** | Regenerated by `python3 scripts/installed_catalog.py` after `catalog.toml` changes |
| Packwiz `*.pw.toml` | packwiz install/remove | Does **not** update `catalog.toml` |

Nothing auto-writes `catalog.toml`. Packwiz, the browser site, and CI only consume it (directly or via `catalog.json`).

## Commit flow (mod add / remove)

1. Install or remove with packwiz; `packwiz refresh`.
2. Update `docs/mods/manifest.md` (and the relevant decision log).
3. Edit `docs/installed/catalog.toml`:
   - Pick the right `[[category]]` / `[[category.group]]`.
   - Add or remove `{ file = "<name>.pw.toml", blurb = "...", tags = [...] }`.
   - `file` must match the packwiz TOML basename.
   - Tags must exist under `[tags]` (or add a new tag there first).
4. Run `python3 scripts/installed_catalog.py` (writes markdown + `catalog.json`).
5. Run `python3 scripts/installed_catalog.py --check` (must exit 0).
6. Update `CHANGELOG.md` `[Unreleased]` when players will notice.
7. Stage TOML, docs, and generated catalog outputs. Never stage jars.

Pre-commit **warns** (does not block) if packwiz TOML is staged without `catalog.toml`. CI (`.github/workflows/installed-catalog.yml`) **fails** the PR if `--check` fails.

## Publish / release flow

Before `python scripts/release.py vX.Y.Z`:

1. Working tree on `main` is clean and includes the latest catalog commit.
2. `python3 scripts/installed_catalog.py --check` passes.
3. `release.py` also runs that `--check` as a one-line preflight and hard-fails if the catalog is out of sync.

After merge to `main`, the browser site (`site/`) loads `docs/installed/catalog.json` from GitHub (poll or push webhook). No separate site deploy is required for list updates unless the site container itself changed.

## Commands

```text
python3 scripts/installed_catalog.py          # rewrite markdown + catalog.json
python3 scripts/installed_catalog.py --check  # validate; no writes
```
